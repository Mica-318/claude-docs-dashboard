What is Prompt Engineering? 什么是提示词工程？

Fundamentals
English

Prompt engineering is the process of optimizing your prompts to get the best possible results from Claude. Think of it like giving clear instructions to someone new to a job—the more precise and well-structured your guidance, the better the results.

Prompt engineering optimizes for two main factors:

  • Quality — Getting more accurate, relevant, and helpful responses
  • Consistency — Making outputs reliably match expectations across many uses
中文

提示词工程是优化你的提示词以从 Claude 获取最佳结果的过程。可以把它想象成给刚入职的人提供清晰指令——你的指导越精确、结构越合理，结果就越好。

提示词工程主要优化两个维度：

  • 质量 — 获得更准确、更相关、更有帮助的回复
  • 一致性 — 让输出结果在多次使用中可靠地符合预期

Before You Prompt 提示前先做这些

Checklist
English

Before diving into prompt engineering, verify that you can't get your desired output by doing the following:

  • Choose the right model for the task — different Claude models have different capabilities
  • Check if simple context or instruction tweaks fix the issue first
  • Look at whether output format adjustments help

Prompt engineering may not be necessary if the simplest prompt already works for your use case.

中文

在深入研究提示词工程之前，先验证能否通过以下方式获得想要的输出：

  • 为任务选择正确的模型 — 不同的 Claude 模型有不同的能力
  • 先检查简单的上下文或指令微调能否解决问题
  • 看看调整输出格式是否有帮助

如果最简单的提示词已经适合你的用例，可能根本不需要提示词工程。

1. Be Clear and Direct 明确且直接

Core Principle
English

Claude responds best to clear, direct instructions. The most common mistake is being too vague — assume Claude needs explicit guidance rather than relying on it to guess your intent.

✅ Good: "Write a 3-paragraph product description for a standing desk, focusing on health benefits. Use a professional tone. End with a call to action."
❌ Too vague: "Write something about our desk."

The golden rule: show your prompt to a colleague and ask if they could follow it exactly as written. If not, it needs clarifying.

中文

Claude 对清晰、直接的指令响应最好。最常见的错误是过于模糊——假定 Claude 需要明确指导，而不是依赖它猜测你的意图。

✅ 好的写法："为一张升降桌写一段 3 段的产品描述，重点关注健康益处，使用专业语气，以行动呼吁结尾。"
❌ 太模糊："写些关于我们桌子的内容。"

黄金法则：把你的提示词给同事看，问他们能否完全按字面执行。如果不能，就需要澄清。

2. Use Examples (Few-Shot) 使用示例（少样本）

Technique
English

Examples are one of the most powerful tools in prompt engineering. When Claude sees examples of what you want, it can pattern-match much more accurately than from description alone.

  • Include 3–5 diverse examples covering different edge cases
  • Make sure examples match your actual use case, not just generic ones
  • Label examples clearly (e.g., Input: / Output:)
  • Ensure examples don't contradict each other
Here are examples of the tone I want:

Input: "The product broke after one use."
Output: "We're so sorry to hear that. Let us make it right immediately."

Input: "When will my order arrive?"
Output: "Great question! We'll track that down for you right now."
中文

示例是提示词工程中最强大的工具之一。当 Claude 看到你想要什么的示例时，它的模式匹配比单纯描述准确得多。

  • 包含 3-5 个涵盖不同边缘情况的多样化示例
  • 确保示例与你的实际使用场景匹配，而不仅仅是通用示例
  • 清晰地标注示例（例如 输入： / 输出：）
  • 确保示例之间不互相矛盾

3. Give Claude a Role 给 Claude 分配角色

Persona
English

Assigning Claude a specific role or persona can significantly improve the quality of responses for specialized tasks.

You are an expert Python developer with 10 years of experience
in backend systems and API design. You write clean, efficient,
well-documented code and always consider edge cases.

Personas work best when they:

  • Specify relevant expertise or background
  • Include key traits that affect how Claude should respond
  • Are realistic and internally consistent
中文

为 Claude 分配特定角色或人格，可以显著提高专业任务的响应质量。

你是一位拥有 10 年后端系统和 API 设计经验的 Python 专家。
你编写简洁、高效、有良好文档的代码，并始终考虑边缘情况。

角色设定效果最好时具备以下特点：

  • 指定相关专业知识或背景
  • 包含影响 Claude 响应方式的关键特征
  • 真实且内部一致

4. Format Output Precisely 精确控制输出格式

Format
English

Tell Claude exactly how you want the output structured. Don't leave formatting to chance.

  • Specify format explicitly: "Respond in JSON with keys: name, price, description"
  • Control length: "Keep your response under 100 words" / "Write at least 500 words"
  • Use markdown purposefully: Only ask for markdown if it will be rendered
  • Request structured sections: "Your response should have: Summary, Key Points, Recommendation"
Pro tip: If you need guaranteed JSON structure, use Structured Outputs rather than prompting alone — it enforces schemas at the API level.
中文

精确告诉 Claude 你想要的输出结构，不要把格式留给机会。

  • 明确指定格式："以 JSON 格式响应，包含字段：name、price、description"
  • 控制长度："回复不超过 100 字" / "至少写 500 字"
  • 有目的地使用 Markdown：只在 Markdown 会被渲染时才要求使用
  • 要求结构化章节："你的回复应包含：摘要、要点、建议"
专业提示：如果需要保证 JSON 结构，使用结构化输出（Structured Outputs）而不仅仅依赖提示词——它在 API 层面强制执行 schema。

5. Think Step by Step 引导逐步思考

Reasoning
English

For complex reasoning tasks, ask Claude to think through problems step by step before giving the final answer. This reduces errors significantly.

Before answering, think through this step by step:
1. Identify all relevant factors
2. Consider potential edge cases
3. Evaluate trade-offs
4. Then provide your final recommendation

Alternatively, use Extended Thinking (see that section) for Claude to reason internally before responding.

中文

对于复杂的推理任务，要求 Claude 在给出最终答案之前逐步思考问题，这可以显著减少错误。

在回答之前，请逐步思考：
1. 识别所有相关因素
2. 考虑潜在的边缘情况
3. 评估权衡
4. 然后提供最终建议

或者，使用扩展思考（Extended Thinking）（见对应章节）让 Claude 在响应前进行内部推理。

6. Long Context Tips 长上下文提示技巧

Context
English

When working with long documents or extensive context:

  • Put documents before questions — Claude performs better when relevant context precedes the query
  • Use XML tags to organize sections: <document>...</document>, <instructions>...</instructions>
  • Remind Claude of its task at the end of a long context window
  • Be explicit about what to focus on: "Based only on the document above..."
中文

处理长文档或大量上下文时：

  • 把文档放在问题前面 — 当相关上下文先于查询时，Claude 表现更好
  • 用 XML 标签组织章节：<document>...</document>、<instructions>...</instructions>
  • 在长上下文窗口末尾提醒 Claude 它的任务
  • 明确指出关注点："仅基于上面的文档……"

7. Chain of Thought & Prefill 思维链与预填充

Advanced
English

Chain of thought: Ask Claude to reason out loud before answering.

<thinking>Let me work through this problem...</thinking>
Based on my analysis above, the answer is...

Prefill technique: Start Claude's response to guide its output direction. Note: Prefilling is not supported on Claude Opus 4.7, Opus 4.6, or Sonnet 4.6. Use structured outputs or system prompt instructions for these models instead.

# Supported on older models only:
messages=[
  {"role": "user", "content": "Is this sentiment positive or negative?"},
  {"role": "assistant", "content": "The sentiment is"}  # prefilled start
]
中文

思维链：要求 Claude 在回答之前大声推理。

<thinking>让我来分析这个问题……</thinking>
基于以上分析，答案是……

预填充技术：开始 Claude 的回复以引导输出方向。注意：Opus 4.7、Opus 4.6 和 Sonnet 4.6 不支持预填充。这些模型请改用结构化输出或系统提示词指令。

Stateless Design 无状态设计

Key Concept

The Messages API is stateless. Every request must include the complete conversation history. Claude has no memory between API calls — you are responsible for storing and resending the full message thread each time.

Messages API 是无状态的。每次请求必须包含完整的对话历史。Claude 在 API 调用之间没有记忆——你负责每次存储并重新发送完整的消息线程。

What is Extended Thinking? 什么是扩展思考？

Concept

Extended thinking gives Claude enhanced reasoning capabilities for complex tasks, providing transparency into its step-by-step thought process before delivering the final answer.

Claude creates thinking content blocks where it outputs internal reasoning. The API response includes thinking blocks followed by text blocks.

⚠️ Important: For Claude Opus 4.7, use Adaptive Thinking (thinking: {type: "adaptive"}). Manual extended thinking is no longer supported on Opus 4.7 and returns a 400 error.

扩展思考为 Claude 提供增强的推理能力来处理复杂任务，在给出最终答案之前透明展示其逐步思考过程。

Claude 创建 thinking 内容块来输出内部推理。API 响应包含 thinking 块，后跟 text 块。

⚠️ 重要：对于 Claude Opus 4.7，使用自适应思考（thinking: {type: "adaptive"}）。手动扩展思考在 Opus 4.7 上不再支持，会返回 400 错误。

Usage — Manual (Sonnet/Haiku) 使用方式—手动模式

Code
client = anthropic.Anthropic()

response = client.messages.create(
    model="claude-sonnet-4-6",
    max_tokens=16000,
    thinking={
        "type": "enabled",
        "budget_tokens": 10000,  # max tokens for internal reasoning
        "display": "summarized"  # "summarized" | "omitted"
    },
    messages=[{
        "role": "user",
        "content": "Are there an infinite number of prime numbers such that n mod 4 == 3?"
    }],
)

for block in response.content:
    if block.type == "thinking":
        print(f"Thinking: {block.thinking}")  # Claude's reasoning
    elif block.type == "text":
        print(f"Response: {block.text}")       # Final answer

display: "omitted" vs "summarized" omitted 与 summarized 的区别

Options

summarized (default on Opus 4.6, Sonnet 4.6): Returns a summary of Claude's full thinking. Charged for full thinking tokens generated, not summary tokens.

omitted (default on Opus 4.7): Thinking blocks returned with empty thinking field. Faster time-to-first-text-token when streaming — server skips streaming thinking tokens entirely.

You're still charged for full thinking tokens even with omitted. Omitting reduces latency, not cost.

summarized（Opus 4.6、Sonnet 4.6 默认）：返回 Claude 完整思考过程的摘要。按生成的完整思考 token 计费，不是按摘要 token。

omitted（Opus 4.7 默认）：思考块以空 thinking 字段返回。流式传输时更快达到首个文本 token——服务器完全跳过流式传输思考 token。

即使使用 omitted，仍然按完整思考 token 计费。omitted 降低延迟，不降低成本。

Interleaved Thinking (Tool Use) 交错思考（工具使用）

Advanced

Claude 4 models support interleaved thinking — Claude can think between tool calls, enabling more sophisticated multi-step reasoning.

  • Opus 4.7 & Opus 4.6: Automatically enabled with adaptive thinking
  • Sonnet 4.6: Automatically enabled with adaptive thinking (recommended)
  • Older Claude 4 models: Add beta header interleaved-thinking-2025-05-14
Key rule: You must pass thinking blocks back to the API unchanged when continuing tool use conversations. Never rearrange or modify them.

Claude 4 模型支持交错思考——Claude 可以在工具调用之间进行思考，实现更复杂的多步推理。

  • Opus 4.7 和 Opus 4.6：自适应思考时自动启用

Best Practices for Tool Definitions 工具定义最佳实践

Tips
  • Write extremely detailed descriptions — This is the #1 factor in tool performance. Aim for 3-4+ sentences per tool. Include what it does, when to use it, what each param means, and important caveats.
  • Consolidate related operations — Instead of create_pr, review_pr, merge_pr, use one tool with an action parameter. Fewer tools = less selection ambiguity.
  • Use meaningful namespacing — e.g., github_list_prs, slack_send_message. Prevents confusion as your library grows.
  • Return only high-signal information — Use semantic IDs (slugs, UUIDs), exclude fields Claude doesn't need. Bloated responses waste context.
  • Use Opus for complex tools — Haiku may infer missing parameters; Opus seeks clarification when needed.
  • 写极其详细的描述 — 这是工具性能的第一要素。每个工具目标 3-4+ 句话。包括：做什么、何时使用、每个参数的含义、重要注意事项。
  • 合并相关操作 — 不要用 create_pr、review_pr、merge_pr，改用一个带 action 参数的工具。工具越少 = 选择歧义越少。
  • 使用有意义的命名空间 — 如 github_list_prs、slack_send_message。随着工具库增长防止混淆。
  • 只返回高信号信息 — 使用语义 ID（slug、UUID），排除 Claude 不需要的字段。臃肿的响应浪费上下文。
  • 复杂工具用 Opus — Haiku 可能推断缺失参数；Opus 在需要时会请求澄清。

What Is a System Prompt 系统提示词是什么

Foundation
English

The system prompt lets you set context, instructions, and persona before the conversation starts. Sent as the system parameter — invisible to end users, persists across all turns.

client.messages.create(
    model="claude-opus-4-7",
    max_tokens=1024,
    system="You are a Python specialist. Always provide runnable code. Never discuss non-programming topics.",
    messages=[{"role": "user", "content": user_message}]
)

Key characteristics:

  • Sent as system parameter, not inside messages array
  • Invisible to end user (unless deliberately leaked)
  • Persists across all conversation turns
  • Claude follows it even if users try to override it
  • Can contain multiple blocks (text + cache_control for Prompt Caching)
中文

系统提示词让你在对话开始前设置上下文、指令和角色。作为 system 参数发送，对最终用户不可见，在整个会话中持续有效。

10要素结构（官方推荐顺序）：

  1. 任务背景（Context）
  2. 语气/角色（Tone / Role）
  3. 具体任务（Task）
  4. 输出规则（Rules）
  5. 少样本示例（Examples）
  6. 用户输入变量（Input data）
  7. 即时任务（Immediate task）
  8. 让 Claude 先思考（Precognition tag）
  9. 输出格式（Output format）
  10. 预填充（Prefill，Opus 4.7 不支持）

Mitigate Jailbreaks & Prompt Injection 防越狱与防提示词注入

Security
English

Claude is inherently resilient to jailbreak attacks, but these strategies add additional layers:

  • Harmlessness screens: Use Claude Haiku 4.5 (lightweight, cheap) to pre-screen all user inputs. Use structured outputs to get simple safe/unsafe classification. Only pass safe inputs to the main model.
  • Input validation: Filter for known jailbreaking patterns. Use an LLM to generalize validation by providing known jailbreak examples.
  • Prompt engineering: Explicitly state ethical and legal boundaries in system prompt. Be specific about prohibited behaviors.
  • Throttle repeat offenders: If user repeatedly triggers refusals, warn and eventually ban.
  • Continuous monitoring: Analyze outputs for signs of jailbreaking. Iteratively refine strategies.
Multi-layer architecture: User input → Haiku screen → [safe] → Main model → Output screening → [clean] → User. This prevents both prompt injection and output leaks.
中文
  • 无害性筛查：用 Claude Haiku 4.5 预筛查用户输入，用结构化输出获取安全/不安全分类。只有安全输入才传给主模型。
  • 输入验证：过滤已知越狱模式。可以提供已知越狱语言作为示例，让 LLM 进行泛化验证。
  • 提示词工程：在系统提示词中明确声明道德和法律边界，具体说明禁止的行为。
  • 限流违规者：用户多次触发拒绝时警告，最终封禁。
  • 持续监控：分析输出中的越狱迹象，迭代优化策略。
多层防护架构：用户输入 → Haiku 筛查 → [安全] → 主模型 → 输出审查 → [干净] → 用户

Reduce Prompt Leak 防提示词泄露

Privacy
English

Warning: Leak-prevention can degrade performance. Use only when necessary. Try output screening first.

  1. Output screening (try first): Post-process outputs. Use regex, keyword filtering, or another LLM to catch leaks before showing to user.
  2. Separate context from queries: Use system prompts to isolate key info. Reemphasize via Assistant prefill (⚠️ not supported on Opus 4.7/4.6, Sonnet 4.6).
  3. Minimize proprietary details: Don't include info Claude doesn't need to perform the task.
  4. Regular audits: Periodically review prompts and outputs for potential leaks.
No method is foolproof. Design assuming a determined attacker will eventually get the system prompt — don't put truly irreplaceable secrets there.
中文
  1. 输出筛查（优先）：对输出进行后处理，用正则/关键词/LLM 捕获泄露
  2. 将上下文与查询分离：系统提示词隔离关键信息
  3. 减少专有细节：不放 Claude 执行任务不需要的信息
  4. 定期审计：定期检查潜在泄露
没有万无一失的方法。设计时假设有决心的攻击者最终会得到系统提示词——不要放不可替代的机密。

What is Prompt Caching 什么是提示词缓存

Core Feature
English

Prompt caching optimizes your API usage by resuming from specific prefixes in your prompts. When the same prefix is reused, the system skips reprocessing it — significantly reducing costs for:

  • Prompts with many examples (few-shot)
  • Large amounts of context or background information
  • Repetitive tasks with consistent instructions
  • Long multi-turn conversations

Two modes: (1) Automatic caching: Add one top-level cache_control — system handles the rest. (2) Explicit breakpoints: Place cache_control on specific blocks for fine-grained control.

Default TTL: 5 minutes. Also available: 1-hour TTL at 2x base input price.

Code

# 只需在请求顶层加一个 cache_control

    model="claude-opus-4-7",
    max_tokens=1024,
    cache_control={"type": "ephemeral"},   # ← 这一行就够了
    system="You are a helpful assistant.",
    messages=[
        {"role": "user", "content": "My name is Alex."},

    ]
)

# 1-hour TTL: cache_control={"type": "ephemeral", "ttl": "1h"}
最容易踩的坑：不要把 cache_control 放在每次请求都变化的块上（如含时间戳或用户消息的块）——会永远写缓存但永远不命中，白花 25% 写入溢价。

import anthropic, time
from anthropic.types.message_create_params import MessageCreateParamsNonStreaming
from anthropic.types.messages.batch_create_params import Request

client = anthropic.Anthropic()

# Step 1: Create batch
batch = client.messages.batches.create(
    requests=[
        Request(
            custom_id="request-001",
            params=MessageCreateParamsNonStreaming(
                model="claude-opus-4-7",
                max_tokens=1024,
                messages=[{"role": "user", "content": "Summarize: ..."}],
            ),
        ),
        # ... up to 100,000 requests
    ]
)

# Step 2: Poll until done
while True:
    batch = client.messages.batches.retrieve(batch.id)
    if batch.processing_status == "ended":
        break
    time.sleep(60)

# Step 3: Stream results (memory-efficient, results may be out of order)
for result in client.messages.batches.results(batch.id):
    match result.result.type:
        case "succeeded":
            print(f"✅ {result.custom_id}: {result.result.message.content[0].text}")
        case "errored":
            print(f"❌ {result.custom_id}: error")
        case "expired":
            print(f"⏱️ {result.custom_id}: expired")

Response Length & Verbosity 响应长度与详细程度

Behavior Change
English

Opus 4.7 calibrates response length to task complexity, not a fixed verbosity. Simple queries get shorter answers; open-ended analysis gets longer ones.

If your product needs consistent output length, add explicit instructions:

# To reduce verbosity:
"Provide concise, focused responses. Skip non-essential context, 
and keep examples minimal."

# Positive examples (what you want) are more effective than 
# negative examples ("don't over-explain")
中文

Opus 4.7 根据任务复杂度自动校准响应长度，不再是固定的详细程度。简单查询得到更短的答案，开放式分析得到更长的答案。

如果你的产品需要一致的输出长度，需要明确指令。关键点：正面示例（你想要什么）比负面指令（不要怎样）更有效。

More Literal Instruction Following 更字面化的指令执行

Key Behavior Change
English

Opus 4.7 is more literal and explicit in how it interprets prompts, especially at lower effort levels:

  • Will not silently generalize an instruction from one item to another
  • Will not infer requests you didn't make
  • If you need Claude to apply an instruction broadly: "Apply this formatting to every section, not just the first one"
✅ Good: More precision and less thrash. Better for carefully-tuned prompts, structured extraction, and predictable pipelines.
⚠️ Watch out: Instructions that previously worked by implication now need to be stated explicitly.

Opus 4.7 解释提示词的方式更加字面化和明确，尤其在较低 effort 级别时：

  • 不会把对某个条目的指令静默推广到其他条目
  • 不会推断你没有明确提出的请求
  • 需要 Claude 广泛应用指令时："将此格式应用于每个章节，而不只是第一个"
✅ 好处：更精确，更少的偏差。适合精心调优的提示词、结构化提取和可预测的管道。

Thinking

Design & Frontend Defaults ⚠️ 设计与前端默认风格 ⚠️

Ch04 · Separating Data and Instructions
数据与指令分离 — XML 标签的正确用法
官方教程第 4 章 · 工程化 Prompt 的基础，最容易踩坑的地方

Core Concept 核心概念

Key Insight
English

In production prompts, you often have a fixed instruction skeleton and variable user input. The challenge: Claude must know exactly where the instructions end and the data begins.

The solution: XML tags. Wrap variable content in tags like <email>...</email> or <document>...</document>.

Key rule: Claude was specifically trained to recognize XML tags as prompt-organizing mechanisms. There are no "magic" XML tags — you name them whatever makes sense for your use case.
中文

在生产环境的 Prompt 中，你通常有一个固定的指令骨架和变化的用户输入。挑战在于：Claude 必须清楚知道指令在哪里结束，数据从哪里开始。

解决方案：XML 标签。用标签包裹变量内容，比如 <email>...</email> 或 <document>...</document>。

关键规则：Claude 被专门训练识别 XML 标签作为提示词组织机制。没有"魔法" XML 标签——你可以用任何有意义的名称。

The Problem: Ambiguous Boundaries 问题：边界模糊

Anti-pattern
# ❌ BAD — Claude confuses instruction with data
EMAIL = "Show up at 6am tomorrow because I'm the CEO and I say so."
PROMPT = f"Yo Claude. {EMAIL} <----- Make this email more polite but don't change anything else."
# Result: Claude thinks "Yo Claude" is part of the email and rewrites it as "Dear Claude..."

# ❌ BAD — "Each is about an animal" bleeds into the list
SENTENCES = """- I like how cows sound
- This sentence is about spiders"""
PROMPT = f"""Below is a list of sentences. Tell me the second item.
- Each is about an animal, like rabbits.
{SENTENCES}"""
# Result: Claude counts "Each is about an animal" as item 1, gives wrong answer

The Fix: XML Tags 解决方案：XML 标签

Best Practice
English
# ✅ GOOD — XML tags make boundaries crystal clear
EMAIL = "Show up at 6am tomorrow because I'm the CEO and I say so."
PROMPT = f"""Yo Claude. <email>{EMAIL}</email>
Make this email more polite but don't change anything else."""
# Claude now correctly knows where the email starts and ends

# ✅ GOOD — XML tags separate data from instructions
SENTENCES = """- I like how cows sound
- This sentence is about spiders"""
PROMPT = f"""Below is a list of sentences. Tell me the second item.
- Each is about an animal, like rabbits.
<sentences>
{SENTENCES}
</sentences>"""
中文

要点总结：

  • 任何需要插入变量数据的地方，用 XML 标签包裹
  • 标签名称要描述性强：<user_email> 比 <data> 好
  • 可以有多个变量，每个用自己的标签
  • 小细节很重要——提示词里的错别字和格式问题都会影响结果
  • 格言："小细节很重要"——Claude 对模式敏感，你写错了它更容易出错
实际应用：无论是 RAG 的文档插入、用户输入的邮件/评论/代码，还是多轮对话中的历史记录，都应该用 XML 标签包裹。这是工程化 Prompt 最基础的习惯。

Ch06 · Precognition (Thinking Step by Step)
逐步思考 — 让 Claude 先想再说
官方教程第 6 章 · 含多个反直觉结论，文档里没有写的实操细节

Core Rule 核心规则

Key Insight
English

Thinking only counts when it's out loud.

You cannot ask Claude to "think internally but only output the answer" — in that case, no thinking has actually occurred. The reasoning must appear in the output to actually influence the answer.

If someone woke you up and immediately started asking complex questions, you'd do worse than if given time to think first. Claude is the same way.

中文

思考只有大声说出来才算数。

你不能要求 Claude "内部思考但只输出答案"——那种情况下实际上没有发生任何思考。推理过程必须出现在输出中，才能真正影响答案。

就像如果有人叫醒你立刻问复杂问题，你的表现会比先思考一下差很多。Claude 也一样。

⚠️ Counter-intuitive: Order Sensitivity 反直觉！Claude 对选项顺序敏感

Surprise!
English

In most situations (not all), Claude is more likely to choose the second of two options. This is because in training data from the web, second options were more likely to be correct.

Demonstrated in the tutorial: when asking Claude to argue both positive and negative, then decide, swapping argument order changes the final answer.

Practical impact: When you ask Claude to evaluate two options (A vs B, approach 1 vs 2), the order you present them matters. Put the option you want more scrutiny on first.
中文

在大多数情况下（不是全部），Claude 更倾向于选择两个选项中的第二个。这是因为在训练数据（来自网络）中，第二个选项更可能是正确的。

教程中的演示：当让 Claude 分别为正面和负面观点辩论，然后做决定时，交换论点顺序会改变最终答案。

实际影响：当你让 Claude 评估两个选项（A 对比 B、方案 1 对比方案 2），呈现顺序很重要。把你想要更严格审视的选项放在第一个。

Practical Patterns 实用模式

Code
# ❌ BAD — Claude gives instant wrong answer
PROMPT = "Is this movie review positive or negative?\n\nThis movie blew my mind. In unrelated news, I've been living under a rock since 1900."
# Claude takes "unrelated" literally and answers "Positive"

# ✅ GOOD — Force Claude to think through both sides first
SYSTEM_PROMPT = "You are a savvy reader of movie reviews."
PROMPT = """Is this review positive or negative? 
First, write the best arguments for each side in <positive-argument> and <negative-argument> XML tags, then answer.

This movie blew my mind. In unrelated news, I've been living under a rock since 1900."""
# Claude now correctly identifies it as negative (ironic/sarcastic)

# ✅ GOOD — Brainstorm tags for factual reasoning
PROMPT = """Name a famous movie starring an actor born in 1956.
First brainstorm actors and their birth years in <brainstorm> tags, then give your answer."""
# Much more accurate than asking directly

Quick Reference 速查：常用思考引导词

Reference
  • "Think step by step before answering."
  • "First brainstorm in <brainstorm> tags, then answer."
  • "Write arguments for both sides in XML tags, then decide."
  • "Before you give your answer, think through..."
  • "Work through this carefully, showing your reasoning."
For Claude 4 models: use Extended Thinking / Adaptive Thinking instead of manual step-by-step prompting for the best results on truly complex problems.
  • "在回答前，请逐步思考。"
  • "先在 <brainstorm> 标签里头脑风暴，再给出答案。"
  • "在 XML 标签里分别写出双方论点，然后做决定。"
  • "在给出答案之前，思考一下……"
  • "仔细推理，展示你的思考过程。"
对于 Claude 4 系列模型：复杂问题用扩展思考 / 自适应思考代替手动逐步引导，效果更好。
Ch08 · Avoiding Hallucinations
避免幻觉 — 两个核心技巧
官方教程第 8 章 · 减少 Claude 编造信息的实用方法

Technique 1: Give Claude an "Out" 技巧一：给 Claude 一条退路

Core Technique
English

Claude sometimes hallucinates because it tries to be as helpful as possible — it will invent plausible-sounding answers rather than admit it doesn't know.

Solution: explicitly tell Claude it's OK to say it doesn't know.

# ❌ Claude hallucinates a confident answer
PROMPT = "Who is the heaviest hippo of all time?"
# Returns: "The heaviest hippo on record was Huberta..." (fabricated)

# ✅ Give Claude permission to not know
PROMPT = "Who is the heaviest hippo of all time? Only answer if you know with certainty."
# Returns: "I don't have reliable data on the specific heaviest hippo..."
中文

Claude 有时会产生幻觉，因为它尽力保持有帮助——它宁愿编造听起来合理的答案，也不愿承认不知道。

解决方案：明确告诉 Claude 说不知道是没问题的。

常用措辞：

  • "只在你确定知道答案时才回答。"
  • "如果你不确定，请说'我不知道'。"
  • "不要猜测——只使用你有把握的信息。"
  • "如果文档中没有相关信息，请明确说明。"

Technique 2: Find Evidence Before Answering 技巧二：先找证据再回答

Core Technique
English

When Claude has a long document to reference, it may fall for "distractor information" — content that's almost but not quite relevant — and give a hallucinated answer.

Solution: ask Claude to find and quote the relevant passage first, then answer based only on that evidence.

# ✅ Force evidence-first answering
PROMPT = f"""Based on the document below, answer the question.

Important: First find the EXACT relevant quote from the document 
and put it in <quote> tags. If you cannot find a relevant quote,
say "No relevant information found" in the tags.
Only then give your answer.

<document>
{long_document}
</document>

Question: {user_question}"""
中文

当 Claude 需要参考长文档时，它可能被"干扰信息"迷惑——那些看起来相关但实际上不是的内容——从而给出幻觉答案。

解决方案：要求 Claude 先找到并引用相关段落，再基于该证据回答。

效果：

  • Claude 被迫先定位原文，再作答
  • 如果文档中没有相关信息，Claude 会明确说"未找到相关引用"
  • 用户可以验证引用是否准确
  • 大幅减少基于文档的问答中的幻觉

Note: Best to put question AFTER document 注意：问题放在文档之后

Ordering Tip

When asking Claude about a long document, put the document before the question, not after. Claude performs better when context precedes the query.

# ✅ Document first, question last
PROMPT = f"""Read the document below and answer the question.

<document>{long_doc}</document>

Question: {user_question}"""

# ❌ Question first (worse for long docs)
PROMPT = f"""Question: {user_question}

<document>{long_doc}</document>"""

向 Claude 询问长文档时，把文档放在问题之前，而不是之后。当上下文先于查询时，Claude 表现更好。

这与人类阅读习惯相同：先读材料，再思考问题，效果优于先看问题再读材料（虽然两种方式都能用）。

Technique
English

Speaking for Claude — Prefill 预填充：替 Claude 开头说话

Technique
English

"Speaking for Claude" means putting words in Claude's mouth via the assistant role — you start Claude's response, and it continues from where you left off.

# Use case 1: Force a specific format from the first character
PROMPT = "Extract all email addresses from this text: [text]"
PREFILL = "["  # Force JSON array format

# Use case 2: Skip unwanted preambles
PROMPT = "Give me the Python function to reverse a string."
PREFILL = "```python"  # Skips "Sure! Here's a function..."

# Use case 3: Multiple-choice — force a single letter answer  
PROMPT = "Is this sentiment (A) positive (B) negative (C) neutral?\nText: [text]"
PREFILL = "("  # Forces answer like "(A)" or "(B)"

response = client.messages.create(
    model="claude-sonnet-4-5",  # Note: not supported on Opus 4.7/4.6

        {"role": "user", "content": PROMPT},

)

"替 Claude 开口"意味着通过 assistant 角色替 Claude 开始回复——你写好开头，Claude 从你留下的地方继续。

  • 强制特定格式：用 "[" 强制 JSON 数组，用 "```python" 强制代码块

Ch07 · Using Examples (Few-Shot Prompting)
少样本示例 — 示例如何让 Claude 外推
官方教程第 7 章 · Few-Shot 是最强大的 Prompt 工具之一，学会用示例替代冗长描述

Core Principle 核心原理

Key Insight
English

Giving Claude examples of what you want is extremely effective for:

  • Getting the right answer
  • Getting the answer in the right format

This is called few-shot prompting. "Shots" = number of examples. Zero-shot = no examples. One-shot = 1 example. N-shot = N examples.

Key insight: Claude doesn't just copy examples — it extrapolates. Show it a pattern, and it applies that pattern to new inputs.

中文

给 Claude 示例对以下两方面极其有效：

  • 获得正确答案
  • 获得正确格式的答案

这叫做少样本提示（Few-Shot Prompting）。"shot（镜头）" = 示例数量。零样本 = 无示例。单样本 = 1 个示例。N 样本 = N 个示例。

关键洞察：Claude 不仅仅是复制示例——它会外推。给它看一个模式，它会把该模式应用到新的输入上。

Example: Tone via Conversation Pattern 示例：通过对话模式传递语气

Code
# Problem: Claude's default answer to children is too formal/robotic
# Solution: Show one example of the right tone — Claude extrapolates

PROMPT = """Please complete the conversation by writing the next line, speaking as "A".

Q: Is the tooth fairy real?
A: Of course, sweetie. Wrap up your tooth and put it under your pillow tonight. 
   There might be something waiting for you in the morning.
Q: Will Santa bring me presents on Christmas?"""

# Claude extrapolates the warm, parent-like tone from the single example
# Output: "Absolutely! As long as you've been good this year, Santa will definitely 
# be stopping by your house on Christmas Eve!"
Key insight: You didn't describe what tone to use — you showed it. One example was enough for Claude to capture the entire character. This is often more effective and less token-intensive than describing tone in words.
关键洞察：你没有描述要使用什么语气——你展示了它。一个示例就足以让 Claude 捕捉整个人物特征。这通常比用文字描述语气更有效，token 消耗也更少。

Few-Shot Best Practices 少样本最佳实践

Reference
  • More examples = better, but even 1-2 can make a dramatic difference
  • Diverse examples covering edge cases outperform many similar examples
  • Label clearly: Use Input:/Output: or XML tags like <example>
  • Consistent format: All examples must follow the exact same structure
  • Don't contradict: Examples that disagree with each other confuse Claude
  • Real examples > synthetic: Use actual cases from your domain when possible
  • 示例越多越好，但即使 1-2 个也能产生巨大差异
  • 涵盖边缘情况的多样化示例优于许多相似示例
  • 清晰标注：使用 输入：/输出： 或 XML 标签如 <example>
  • 格式一致：所有示例必须遵循完全相同的结构
  • 不要矛盾：相互矛盾的示例会让 Claude 困惑
  • 真实示例 > 合成示例：尽可能使用来自你领域的真实案例
Ch10 · Prompt Chaining
提示链 — 让 Claude 自我校验与迭代
官方教程第 10 章附录 · Writing is rewriting — Claude can improve its own outputs

Core Idea 核心思路

Key Insight
English

"Writing is rewriting." Claude can often improve the accuracy of its response when asked to do so. The natural ways you'd ask a human to double-check their work also work for Claude.

Prompt chaining = using Claude's output from one call as input to the next. This enables:

  • Self-verification and error correction
  • Iterative quality improvement
  • Breaking complex tasks into manageable steps
  • Using one Claude call to structure another
中文

"写作即改写。" 当被要求这样做时，Claude 通常能提高其回答的准确性。你让人类复查工作的自然方式对 Claude 同样有效。

提示链 = 将 Claude 一次调用的输出作为下一次的输入。这实现了：

  • 自我验证和错误纠正
  • 迭代质量提升
  • 将复杂任务分解为可管理的步骤
  • 用一次 Claude 调用来结构化另一次

Pattern 1: Self-Verification 模式一：自我验证

Code
# Step 1: Get initial answer (may contain errors)
first_user = "Name ten words that all end with the exact letters 'ab'."
messages = [{"role": "user", "content": first_user}]
first_response = get_completion(messages)
# Claude might include fake words like "trab", "scrab"

# Step 2: Ask Claude to verify its own answer
second_user = "Please find replacements for all 'words' that are not real words. \
If all the words are real words, return the original list."
# ↑ IMPORTANT: Give Claude an "out" — it won't change things unnecessarily

messages = [
    {"role": "user", "content": first_user},
    {"role": "assistant", "content": first_response},  # Claude's first attempt
    {"role": "user", "content": second_user}           # Ask it to self-check
]
corrected_response = get_completion(messages)
# Now Claude removes the fake words and replaces them with real ones
Critical: Without the "out" ("if all correct, return original"), Claude will sometimes change correct words unnecessarily to appear helpful. Always give Claude permission to leave things unchanged.
关键点：没有"退路"（"如果全部正确，返回原始列表"），Claude 有时会不必要地修改正确的词，以显得有帮助。始终给 Claude 保持不变的许可。

Pattern 2: Output → Refinement 模式二：输出→精炼

Iterative
# Step 1: Draft
first_user = "Write a three-sentence short story about a girl who likes to run."
messages = [{"role": "user", "content": first_user}]
first_response = get_completion(messages)

# Step 2: Ask Claude to improve its own draft
messages = [
    {"role": "user", "content": first_user},
    {"role": "assistant", "content": first_response},
    {"role": "user", "content": "Make the story better."}
]
improved = get_completion(messages)
# Claude's second version is almost always noticeably better

Pattern 3: Extract → Transform → Use 模式三：提取→转换→使用

Pipeline
# Use Claude's output as input to another Claude call
# Step 1: Extract names from text
first_user = """Find all names from the below text:
"Hey, Jesse. It's me, Erin. I'm calling about the party that 
Joey is throwing. Keisha said she would come and Mel will be there too." """

messages = [{"role": "user", "content": first_user}]
first_response = get_completion(messages)
# Returns: Jesse, Erin, Joey, Keisha, Mel

# Step 2: Pass extracted names to a new task
messages = [
    {"role": "user", "content": first_user},
    {"role": "assistant", "content": first_response},
    {"role": "user", "content": "Alphabetize the list."}
]
alphabetized = get_completion(messages)
# Returns: Erin, Jesse, Joey, Keisha, Mel
This is the foundation of "function calling": Use Claude to perform some function (extraction, analysis, classification), then feed results into another Claude call for further processing. You can build pipelines of arbitrary depth.

When to Use Prompt Chaining 何时使用提示链

Decision Guide
  • ✅ Task has verifiable intermediate outputs — extract names, then sort them
  • ✅ Quality needs iterative improvement — draft → review → polish
  • ✅ Task is too complex for one prompt — break into sequential steps
  • ✅ First output needs self-verification — generate → check → fix
  • ❌ Simple, well-defined tasks — one good prompt is enough
  • ❌ When you need speed — each chain step adds latency
  • ✅ 任务有可验证的中间输出 — 提取名字，然后排序
  • ✅ 质量需要迭代改进 — 草稿→审查→润色
  • ✅ 任务对单个提示词太复杂 — 分解为顺序步骤
  • ✅ 首次输出需要自我验证 — 生成→检查→修复
  • ❌ 简单、定义明确的任务 — 一个好的提示词就够了
  • ❌ 需要速度时 — 每个链步骤都会增加延迟

Effort Parameter — 控制智能 vs 成本 调节智能深度的核心旋钮

Opus 4.7 关键
English

The effort parameter lets you tune Claude's intelligence vs. token spend. This is more important for Opus 4.7 than any prior model.

LevelBest For
maxIntelligence-demanding tasks; may have diminishing returns or overthinking
xhigh ⭐ NEWRecommended for coding & agentic use cases
highMost intelligence-sensitive use cases (minimum recommended)
mediumCost-sensitive; reduces tokens, trades off intelligence
lowShort, scoped, latency-sensitive, non-intelligence-sensitive tasks

Key change from 4.6: Opus 4.7 respects effort strictly at low end — at low/medium it scopes work to exactly what was asked, no going above and beyond. Risk: under-thinking on complex tasks at low.

Adaptive Thinking Control 自适应思考控制

Opus 4.7
English

Opus 4.7 thinks adaptively — it decides when to think based on task complexity. This behavior is steerable:

Reduce thinking (for large/complex system prompts that over-trigger):

Thinking adds latency and should only be used when it will meaningfully improve answer quality — typically for problems that require multi-step reasoning. When in doubt, respond directly.

Force thinking on hard tasks at medium effort:

This task involves multi-step reasoning. Think carefully through the problem before responding.

Literal instruction following (new in 4.7): Will NOT silently generalize from one item to another. State scope explicitly: "Apply this formatting to every section, not just the first one."

中文

Opus 4.7 会自适应地决定何时思考，这个行为可以通过提示词控制：

  • 减少思考：在系统提示词复杂时可能过度触发，用上面的模板控制
  • 在 medium 努力级别强制思考：对复杂任务显式要求

English

Core Concept

Task Budgets (Beta) — Agentic Loop Token 预算
仅 Claude Opus 4.7 · Beta Header: task-budgets-2026-03-13 · 软限制非硬截断

What & When to Use 是什么 · 何时用

Beta
English

Task budgets tell Claude how many tokens it has for a full agentic loop — including thinking, tool calls, tool results, and output. Claude sees a running countdown and uses it to prioritize work and finish gracefully.

Use when:

  • You want Claude to self-regulate token spend on long-horizon tasks
  • You have a predictable per-task cost or latency ceiling
  • You want the model to finish gracefully (summarize, report progress) as it approaches the budget — not cut off mid-action
⚠️ Advisory, not enforced: Claude may exceed the budget if stopping mid-action is more disruptive. Hard cap is still max_tokens per request. Minimum budget: 20,000 tokens. Too-small budget → refusal or aggressive scoping.
中文

Task budget 是跨整个 agentic loop（多个请求）的 token 花费上限，包含思考/工具调用/结果/输出。模型看到倒计时并自我调节，在预算耗尽前优雅收尾。

软限制不是硬截断：预算不够时 Claude 会拒绝/缩减工作量，而不是静默截断。预算最小 20,000 token，太小会导致任务被拒或激进缩减。

参数作用与 task_budget 关系
max_tokens单次请求硬截断正交，可同时设置
effort每步推理深度互补：effort 控深度，budget 控总量
Adaptive thinking自动调节思考量思考 token 计入预算，预算耗尽时自然缩减
Prompt caching缓存节省费用每轮改 remaining 会破坏缓存前缀
上下文压缩时：如果在请求间重写/摘要了上下文，服务端丢失了先前花费记录，需手动传 remaining: total - tokens_spent_so_far。
